# Cookbook API

![CI](https://github.com/seriousevgeniy-cpu/Python_Advanced/actions/workflows/ci.yml/badge.svg)

Асинхронный бэкенд кулинарной книги на FastAPI + асинхронной SQLAlchemy
(SQLAlchemy 2.0, `aiosqlite`).

## Структура

* `database.py` — асинхронный движок и сессия (сессия создаётся заново на
  каждый запрос через `Depends(get_session)` — в отличие от примера из
  материалов урока с одной общей на всё приложение сессией, что небезопасно
  при параллельных запросах).
* `models.py` — ORM-модели `Recipe` и `Ingredient` (один-ко-многим).
* `schemas.py` — Pydantic-схемы для трёх разных представлений: список
  рецептов, детальная карточка рецепта, тело запроса на создание.
* `crud.py` — работа с БД, отдельно от HTTP-роутов.
* `main.py` — сами эндпоинты.
* `seed_data.py` — наполняет БД несколькими рецептами для ручной проверки.
* `tests/test_recipes.py` — тесты на `TestClient` (задание со звёздочкой).

## Эндпоинты

* `GET /recipes` — список всех рецептов (название, просмотры, время
  готовки), отсортированный по популярности (просмотры по убыванию, при
  равенстве — по времени готовки по возрастанию).
* `GET /recipes/{recipe_id}` — детальная карточка рецепта (название, время
  готовки, ингредиенты, описание). Каждый успешный вызов увеличивает
  счётчик просмотров на 1. 404, если рецепта с таким id нет.
* `POST /recipes` — создать новый рецепт.

Полная интерактивная документация — на `/docs` (Swagger UI) и `/redoc`.

## Запуск

```bash
pip install -r requirements.txt
python seed_data.py       # наполнить БД примерами (по желанию)
uvicorn main:app --reload
```

Откройте `http://127.0.0.1:8000/docs`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/ -v
```

Тесты используют отдельную in-memory SQLite (через `dependency_overrides`),
файловая БД приложения не трогается.

## Линтеры

```bash
pip install -r requirements-dev.txt
flake8 .
isort --check-only .
black --check .
mypy .
```

`black` и `flake8` по умолчанию конфликтуют по паре правил (`E203`, `W503`
срабатывают именно на том стиле пробелов/переносов, который сам же
расставляет `black`) — это задокументированная особенность `black`, и
решается она конфигурацией: правила отключены в `.flake8`
(`extend-ignore = E203, W503`), а `isort` переведён в `profile = "black"`
(`pyproject.toml`), чтобы сортировка импортов не спорила с форматированием.

## CI

GitHub Actions (`.github/workflows/ci.yml`) запускает flake8, isort, black
и mypy, затем pytest — при пуше в любую ветку и при открытии PR.

## Проверка CI

Эта секция подтверждает, что CI запускается и на пуш в отдельную ветку, и на PR.
